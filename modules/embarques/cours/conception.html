Exigences de conception (Requirements Design)

Tu dois concevoir la semelle connectée. Avant d'écrire une ligne de code, il faut choisir la puce, décrire le comportement attendu, décider du langage et fixer ce que le système doit garantir. Le cours range ces décisions en quatre familles.

Intuition

Concevoir un système embarqué, c'est répondre à quatre questions. Sur quoi tourne-t-il ? C'est le matériel. Comment se comporte-t-il ? On le dessine avant de le coder : c'est la modélisation. Comment le programme-t-on, et que fait le programme ? C'est le logiciel. Qu'est-ce qui doit être garanti, et à quel prix ? Ce sont les exigences.

Les exigences pilotent tout le reste : un délai très court impose une puce rapide et des interruptions, une exigence de sécurité impose de vérifier chaque comportement, un coût bas impose une puce modeste.

Formalisation

FamilleContenu du cours
Hardware (matériel)Microcontrollers, Embedded Controllers, DSP, …
Modelling (modélisation)flowcharts, state machines/diagrams, RT UML, SysML, …
Software (logiciel)langages : assembler, C/C++, python, …
Requirements (exigences)Responsiveness (time), Reliability, Safety, Verification, Cost, …

Le logiciel embarqué remplit quatre fonctions :

  • read data from input ports : lire les données sur les ports d'entrée ;
  • send data to output ports : envoyer des données sur les ports de sortie ;
  • internal data transfer and mathematical operations : déplacer les données en interne et calculer ;
  • timer interrupt facilities for timing the controller algorithm : utiliser les interruptions d'un timer pour cadencer l'algorithme de commande.

Les exigences, une à une : Responsiveness (time), répondre dans un délai donné ; Reliability, fonctionner sans panne dans la durée ; Safety, ne pas mettre en danger le patient ou l'utilisateur ; Verification, pouvoir prouver que le système fait ce qu'il doit ; Cost, tenir un coût.

Une machine à états (state machine) est l'un des outils de modélisation cités : elle décrit les situations possibles du système et les événements qui font passer de l'une à l'autre. Un organigramme (flowchart) décrit la suite des opérations d'un programme, comme la boucle ci-dessus.

Exemple

Exemple ajouté : les quatre familles appliquées à la semelle connectée.

FamilleDécision pour la semelle
Hardwareun microcontrôleur sobre (µC), avec ADC pour les 16 capteurs et une radio
Modellingun organigramme de la boucle de mesure, une machine à états (repos, mesure, envoi)
Softwaredu C, avec les quatre fonctions : lire les capteurs, calculer, envoyer, cadencer par timer
Requirementsmesure toutes les 10 ms (Responsiveness), plusieurs jours sur accumulateur (Cost et ressources), jamais d'alerte manquée (Safety, Verification)

Formules clés

Conception = Hardware + Modelling + Software + Requirements. Quatre fonctions du logiciel : lire les entrées, écrire les sorties, transférer et calculer, cadencer par interruption de timer. Exigences : temps de réponse, fiabilité, sécurité, vérification, coût.
